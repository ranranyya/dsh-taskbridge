# 1.5.3 — 验收展示、混合换行与指挥规则修复

日期：2026-11-17（Asia/Shanghai）。这是基于 1.5.2 的小更新，汇总已安装验证的 1.5.3-test.2 候选。

## 本次更新

- **验收摘要更清楚。** 任务卡片只显示结论、时间和保存状态，完整审查意见在详情中阅读；保存尚未确认或失败时不提前显示通过。
- **完整意见正常换行。** 长路径和连续字符串在容器内换行，保留全部正文和原始换行，继续支持按需读取、复制及刷新。
- **修复 Codex 模板换行识别。** 未修改的已知模板可采用 LF、CRLF 或逐行混合换行，避免仅因换行差异被误判为用户修改。新写入统一 LF；正文、空白、BOM、独立 CR 和版本改动继续受到保护，写入和删除前仍精确复核原字节。
- **加入指挥端规划与按需拆单规则。** 指挥端先明确目标、方案、责任和验收，再派当前可执行的工单；交付后集中审查，修正续接原任务。简单内聚任务可以一次完成，不强制机械拆分。
- **支持测试版升正式版。** 保留正式 1.5.2 以及真实本地 test.1／test.2 原版模板的准确身份；自定义规则继续保留，不用当前正文伪造旧模板。

## 更新方法

在 DSH 的 **插件 → 添加插件** 中输入：

```text
dsh-taskbridge@1.5.3
```

也可安装本项目 GitHub Release 提供的 `dsh-taskbridge-1.5.3.tgz`，或使用本项目自定义插件索引。区域镜像尚未同步时可切换 npm 官方源。

启用新版后，在 **Codex 集成** 中确认就绪；未修改的受管模板可在启动时升级，也可点击 **安装 / 更新 TaskBridge 智能体**。用户编辑过的规则不会自动覆盖，应先确认并自行处理冲突。重新加载 Codex 后使用新规则和工具说明，已打开的聊天可能仍保留旧说明。

## 验证与边界

- test.2 候选已完成 1604 项全库回归、实际原生插件安装、验收摘要和完整意见界面检查，以及真实 Codex／MCP 就绪核对。候选界面样本的 792 字符正文与后台逐字一致，无横向溢出。
- 正式版针对真实 test.2 模板补充升级及编辑保护检查，并重新检查版本、包内容、客户端构建和回归。正式包的最终统计与校验值见本 Release 的验证摘要和 SHA256 附件。
- 正式源码完整回归 **1611/1611 通过**，0 失败、跳过或取消；相关定向检查最终 20/20 通过，客户端产物一致性检查通过。首次定向检查中的交替换行夹具构造问题已修正，未放宽产品识别或用户内容保护。
- 混合换行只用于准确识别全文等价，不授权覆盖其他用户修改。旧记录已经丢失的正文不会因升级恢复；任务历史仍沿用既有容量轮换策略。
- 指挥规则是行为约定，不是强制所有模型遵守规划流程的运行时拦截器。用户选择的提供方、模型与思考强度、权限判断及静默等待协议继续沿用。
- 本次不新增任务名称保存、分组或目标树，不新增执行通道，不宣称新的 token 节省比例。当前支持 Codex；Claude Code／Claude Desktop 接入仍为预计 2.0 的计划。
- 发布与本机安装分别记录；正式版发布不会自动把本地 test.2 安装来源改为 npm。
