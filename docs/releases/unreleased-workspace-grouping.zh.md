# 侧栏：原生工作区保持不变，派工对话带标记（待发布版本）

> 版本号与是否发布由宿主决定；本文件只写已经实现的用户可见变化，不含版本声明。

- **原生工作区栏不变**：DSH 自己的「工作区」列表（名称、顺序、搜索、会话行、菜单、打开/新建/
  重命名/移除/归档/恢复）完全由宿主渲染，本插件不再注册该区域，因此不会被替换、遮挡或筛选。
- **派工对话有标记**：经 TaskBridge 派出的会话，在其原生行里多一个很小的内联标记：共享派工
  显示「派工」，隔离派工显示「派工 · 隔离」，悬停显示任务标题。不是本插件派出的会话没有任何
  变化。
- **TaskBridge 分组在插件自己的面板里**：严格三层 **TaskBridge → 任务工作区 → 对话**，每个派工
  链一行。同一项目两次独立派工各占一行；续接沿用父任务的工作区与会话，只显示一行。
- **真 ID 的操作**：打开、新建会话、归档/恢复、任务工作区的重命名与移除都走 DSH 自己的接口和
  真实 ID。**混有你自己普通对话的工作区不会被整项重命名或移除**，按钮会说明原因。
- **实时**：归档、恢复、新工作区与新派工都会在宿主推送后直接反映，无需重载。

## 已知宿主接口缺口（如实说明）

DSH 0.2.2-rc.5 把工作区浏览器放在**单一** slot `sidebar.workspaces` 里，且不提供「在该浏览器
上方再放一栏」的 slot，也不公开它的组件。因此「同级相邻、上 TaskBridge 下原生工作区」这种排布
无法通过公开扩展点实现——上一版直接接管该 slot，结果导致原生行消失（验收日志已记录）。本版改为：

1. 原生区域完全交还宿主（不注册该 slot）；
2. 只用宿主**已公开的子 slot** `sidebar.workspaces.session.row.action` 在原生会话行内加标记；
3. 分组画在插件自己的面板上。

若宿主愿意，最小扩展是新增一个位于 `sidebar.workspaces` **上方**的同级 slot（或公开
`WorkspaceBrowser` 组件），即可实现原来的上下相邻两栏。详见 `docs/workspace-grouping.md`。
