# DSH TaskBridge 1.9.3 更新说明

## 摘要

`1.9.3` 在保持既有安全隔离、单写者纪律与无感升级边界的前提下，新增 **隔离工作树（`worktree`）验收后零破坏自动写回原仓库（`applyToSource` / `sourceSync`）**，并基于双端全集基准复验进一步打磨 **Codex 首轮契约防坑指引、验收收尾零冗余与 Windows 单次测试审批边界**：

1. **隔离工作树（`worktree`）验收后零破坏自动写回（`delegate_review.applyToSource`）**：
   - 新增独立同步模块 `src/workspace/sync-source.js`，并在 `delegate_review` / `POST /tasks/review` 接入可选布尔参数 `applyToSource`（默认 `false`，仅在 `decision: "accepted"` 时允许传 `true`）。
   - **严格先持久化验收、再执行冲突预检写回**：仅当 `reviewPersistence.state === "saved"` 且 `durable: true` 落盘确认且委派总开关开启时触发；写回前按规范路径字典序同时锁定 `sourcePath` 与 `executionWorkspacePath`，逐一校验双端 Git 根目录与基线 `HEAD === baseHead`、拦截路径穿越 / `.git` / 符号链接（含磁盘链接与 Git `120000` / 子模块 `160000`）与敏感路径、保护 `sourcePath` 非重叠未提交草稿并对重叠修改或 `git apply --check` 失败执行**零字节改动中止**（返回有界 `conflictingPaths`，且绝不回滚已保存的 `accepted` 验收记录）。
   - 预检通过后应用已追踪文件的二进制或文本补丁，逐文件原子写入未追踪的新文件，并清理因删除或重命名变空的子目录。`sourceSync` 回执包含 `applied`、`reason`、`changedFiles` 和 `conflictingPaths`。源目录已包含同样的改动时返回 `already-synced`。写入开始后若遇到磁盘或权限错误，先前写入的文件可能已生效。插件全程无需执行 `git add`、`git commit`、`stash` 或 `push`。
   - Codex 与 Antigravity 双端派工规范同步收口：单任务或整条多阶段任务链最后一个工作包最终 `accepted` 时直接传 `applyToSource: true`（中间子包与 `changes-requested` 省略），彻底省去宿主端在验收后另起 PowerShell / Node 脚本手工拷贝补丁或回源目录重跑测试的额外回合。
2. **Codex 端派工契约提厚、收尾零冗余与单次测试审批澄清**：
   - `P0` 派工规范引导将派工前只读探查合并为 1–2 次读取，并在首轮 `delegate_submit.prompt` 中提前点明高发契约雷区（精确导出签名与封闭返回字段集、十进制字符串/有理数缩放防漂移、`Object.hasOwn` 原型安全查找、按规范区分 `??` 与 `=== undefined` 避免 `||` 误吞合法假值、真实子进程 CLI 退出码测试与 `os.tmpdir()` 临时目录）；同时明确 `sourceSync.applied === true` 后禁止在 `sourcePath` 追加多余哈希或 Git 复检命令，并将 Codex 技能入口/附页读取预算上调至 `16,000 / 24,000` UTF-8 字节。
   - 在 `permission` 审批规则中明确：Codex 自身的 `approval_policy` 不限制批准安全的 DSH Worker 单次调用；当 Worker 请求在任务工作区内单次运行本包必需的测试、构建或只读 Git 检查（含 Windows 下因沙箱管道/ACL 限制触发 `requestedAccess.kind === "sandbox-escalation"` 且 `standingModeUnchanged: true`、`allowBlocked: null` 的情形）时，应授予 `allow-once` 以便 Worker 在交付前完成自测闭环。
3. **双端 7 题黑盒基准省流创新高与无感升级哈希补登**：
   - **Antigravity 端（`v1.9.3-test1`）**：`7/7`（`700/700`）满分且全程 **0 返工**，`T1–T5` 主控均步压降至 **`10.00` 步**（低于无插件基线的 `11.00` 步，7 题均步 **`8.29`**），`T1–T5` 强模型有效 Token 较基线**净省 `39.43%`**（`618,861 → 374,844`，强模型代码输出**净省 `64.53%`**），且**强模型含缓存总 Token 首次实现正向净省 `33.61%`**（`3,276,639 → 2,175,330`，较 `1.9.1` 净降 `35.30%`；重型三域重构题 `T5` 有效净省 **`52.10%`**、总 Token 净省 **`44.63%`**）。
   - **Codex 端（`1.9.3-test1` / `test2` 连续两轮全集）**：连续两轮 `7/7`（`700/700`）满分通过（`T2` 超越无插件基线 `80 → 100`），全部 `worktree` 题 `100%` 零冲突自动写回原仓库并通过源目录直接黑盒阅卷，验收后手写同步命令清零为 **`0`**；`T1–T5` 主控有效 Token 较无插件基线**净省 `26.47%–28.10%`**（`608,065 → 437,191–447,111`，主控输出**净省 `28.83%–37.40%`**），7 题含缓存总 Token 进一步压降至 **`600.6 万–646.3 万`**（刷新 Codex 全满分场历史最低纪录，较 `1.9.1` 满分场降 **`43.3%–47.3%`**、较 `1.9.2` 含写回场 `751.1 万` 再降 **`13.9%–20.0%`**；`T5` 有效净省 **`47.61%–51.42%`**、输出净省 **`55.3%–60.3%`**）。
   - 在 `src/codex/installer.js` 与 `src/antigravity/installer.js` 中补登已发布 `1.9.2` 及 `1.9.3-test1` / `test2` 托管技能的精确 SHA-256 哈希，保障既有托管安装无缝自动升级并保留用户自定义修改。

## 升级说明

- **从 `1.9.2`、`1.9.1`、`1.9.0` 或更早版本升级**：在 DSH 插件管理页直接升级或本地安装 `dsh-taskbridge-1.9.3.tgz` 并启用；DSH 启动自检会自动将未修改过的旧版 Codex / Antigravity 托管技能刷新至 `1.9.3`（也可在插件设置页对应集成标签手动点击更新），重开宿主会话即可生效。既有接口配置、本机调用开关与历史任务记录全部原样保留。
