# 1.5.3-test.1 本地测试版说明

日期：2026-11-16。基于正式版 1.5.2，只更新指挥规则及其迁移支持。

## 本次效果

指挥端先明确总目标、主要方案、接口、依赖及验收，再选择当前工作包派给 DSH。简单且内聚的任务仍可一次完成；包含可分离阶段的大任务必须按需拆分。执行端只负责当前工单，不能自行实现整个路线图。

每单交付后，指挥端集中审查、记录结论，再推进依赖任务。有问题续接该任务；独立工作使用新会话。规划、规则、报告及更新日志由指挥端编写。只验证的工单不允许修改候选规则、实现或测试断言。

派工工具的说明同步增加提醒。API、执行模型、思考强度仍取自用户设置；审批、静默等待和续接机制保持原有协议。

## 安装与验证

1. 在 DSH 插件管理器中添加本地 `dsh-taskbridge-1.5.3-test.1.tgz`。这是同一插件的预发布包，会更新该 profile 中的 TaskBridge。
2. 启用插件后，确认设置页的 Codex 集成已更新到 `1.5.3-test.1`；需要时点击更新 Codex 集成。
3. 使用新的 Codex 对话或重新加载集成后再测试 `@dsh-taskbridge`。包内新规则不会改变已开始的执行任务。
4. 用一个包含多个阶段的需求验证：指挥端先给出方案和当前小工单，DSH 交付并审查后才推进下一阶段。

已发布 1.5.2 原版模板的 LF／CRLF 升级、重复更新及用户自定义规则保留有自动测试覆盖。此前 P0 候选的 184 项规则与协议测试通过；本测试包另做版本、分发和解包验证，具体结果随本地验证报告提供。
