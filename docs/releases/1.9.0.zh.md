# DSH TaskBridge 1.9.0 更新说明

## 摘要

`1.9.0` 完成了 **Codex 原生技能（Skill + 按需附页）单链直等架构升级**、**跨宿主分层派工内核重构**、**多阶段隔离工作树复用与 MCP 往返减负**，以及 **DSH 插件市场「立刻启用」瞬间 404 竞态修复**：

1. **Codex 从子智能体升级为原生技能（Skill）单链直等架构**：托管目标由旧版 `agents/dsh-taskbridge.toml` 升级为 `$CODEX_HOME/skills/dsh-taskbridge/SKILL.md` 及同目录哈希固定附页 `rules-reference-<sha256>.md`，让当前 Codex 会话在明确指派时读入紧凑入口并直调 `delegate_submit({ autoPreflight: true, wait: true })` + 单链 `delegate_wait`（配合 `tool_timeout_sec = 3660` 静默长等），根除 `spawn_agent` + 短超时 `wait_agent` 每 45–55 秒轮询空转。
2. **老版本子智能体无感安全退役**：自动识别未修改过的 `0.1.6`–`1.8.x` 旧托管 `agents/dsh-taskbridge.toml` / `agents/dsh-delegate.toml`，在确保新技能落盘且写入前二次逐字节复验后安全删除；用户自定义编辑过的旧文件原样保留并提示。
3. **跨宿主分层派工内核重构与双端理念对齐**：源码层将跨平台公共派工内核（`integrations/core/`）与各宿主薄适配壳（`integrations/adapters/`）分离并通过 `npm run build:integrations` 统一组装、单测锁死零漂移；双端统一为「**大任务拆小包 + 指方向与契约防跑偏（禁代写逐行代码）+ 务实审查防洁癖返工**」，Antigravity 同步收紧主控与 `flash` 子智能体省流边界。
4. **跨子包隔离工作树复用与 MCP 往返压缩**：
   - `delegate_submit` 新增 `reuseWorktreeFromTaskId`（下游子包复用上游已验收隔离 `worktree` 并开启全新 DSH 会话，全程不污染主仓库，联动清理自动做引用保护）及 `autoPreflight` / `wait` 单次调用合并；
   - 正式版的 `delegate_permission_decide` 按本次调用的精确参数指纹逐次审批。预览版客户端通过 `allow-once` 传入 `scope: "task-command"` 时，正式版按单次审批 `scope: "once"` 处理。
   - `delegate_result` 新增 `includeDiff: false`（本地审查 `executionWorkspacePath` 时免去重复回传大段补丁），任务回执补充 `execution.usage.delta` 与 `cumulative` 双口径统计。
5. **彻底修复 DSH 插件市场「立刻启用」瞬间 404**：后端先注册 HTTP 路由再并行执行启动刷新，前端冷启动遇到短暂 404 时静默退避重试并自动恢复，不再连弹多条红框。

## 双端 7 题黑盒基准实测摘要（`1.9.0-test6` 候选构建 vs 同宿主无插件基线）

以下为 `1.9.0-test6` 候选包的黑盒基准实测。用例覆盖边界拦截（`T0A`/`T0B`）、核心模块实现（`T1`–`T4`）和含 235 项单测的企业级三域计费平台重构（`T5`）。DSH 后端采用轻量模型 `deepseek-v4.1-flash`。

- **Antigravity 端（`gemini-4-neon-xhigh` 主控 + `flash` 后台子智能体）**：`7/7` 全满分通过（均分 `100`，`T1–T5` 同题得分与无插件基线 `5/5` 持平），`T1–T5` 同题主控平均步数 `11.00 → 11.80` 步基本持平（7 题全集均步 `9.57`），`T1–T5` 同题强模型**有效 Token（非缓存输入 + 输出）净省 `32.06%`**（`618,861 → 420,450`，其中 `T5` 净省 **`37.95%`**，`T1`/`T2`/`T3` 连含缓存总 Token 也比基线低 `9.8%`–`19.2%`）。
- **Codex 端（`gpt-6.2-sol / xhigh` 主控 + 原生 Skill 单链直等）**：`6/7` 通过，`T1–T5` 同题通过 `4/5`（均分 `96`）且逐题得分与无插件 Codex 基线 **100% 一致**（`T5` 满分通过，`T2` 两组显式传入超额策略补测均满分），`T1–T5` 同题主控平均步数 `11.20 → 28.60` 步（7 题全集均步 `21.29`），`T1–T5` 同题主控**有效 Token 净省 `24.50%`**（`608,065 → 459,102`，其中 `T5` 净省 **`43.32%`**、主控输出 Token 降 `47.9%`；7 题有效 Token 较旧轮询态 `2,367,661` 暴降 **78.7%**）。
- **结论要点**：多文件实现与跨模块重构（`T2`/`T3`/`T5`）强模型有效 Token 稳定节省 **13%–43.3%** 且同题得分与无插件基线完全持平；几分钟可改完的极小单点修改（`T4`）存在固定调度开销，建议直接在指挥端顺手完成。

## 升级说明

- **从 `1.8.1` 或更早版本升级**：在 DSH 中安装 `1.9.0` 并启用后，DSH 启动刷新会自动把未修改过的旧 `agents/dsh-taskbridge.toml`（及测试版 `SKILL.md`）迁移为最新 `skills/dsh-taskbridge/SKILL.md` + 规则附页并清理旧文件；随后新开 Codex 会话或重启 Codex 即可生效。
- **如果项目 `AGENTS.md` 仍写了“派给子智能体 `dsh-taskbridge`”**：建议同步改为由当前 Codex 会话按 `skills/dsh-taskbridge/SKILL.md` 直接执行单链 `delegate_submit` + `delegate_wait`，避免再次触发 `spawn_agent` + `wait_agent` 轮询。
